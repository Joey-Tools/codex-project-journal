# Codex Project Journal

Public Codex skill and helper scripts for lightweight per-workstream project journals in repositories whose policy requires the workflow, that contain a valid tracked non-generated journal entry, or that have an explicit durable-state need.
The skill does not bootstrap trackers, generated indexes, or local hooks across repositories by default.
An empty `docs/project_journal/` directory or generated `INDEX.md` does not establish adoption.
Adoption checks validate exact unconflicted stage-0 regular-file blobs from the Git index, not substituted worktree paths or content.
Before any repository Git read, the helper opens one resolved Git executable with required `O_NOFOLLOW|O_NONBLOCK`, binds the selected pathname and descriptor to the same initial regular-file identity and access policy, and copies stable content under a 64 MiB ceiling and one monotonic time budget into an owner-private immutable-by-policy snapshot. Snapshot creation closes its source, destination, and directory descriptors through one bounded precedence helper: an active copy, verification, or deadline failure remains the exact primary with bounded close evidence, while an otherwise-successful close failure becomes primary and removes the snapshot or reports its retained cleanup locator. It accepts only snapshotted ELF or Mach-O native launchers; script wrappers and unknown executable formats fail closed because private-copy execution cannot preserve their relative interpreter or wrapper location semantics. It requires those exact bytes to return a bounded credential-free Git 2.45-or-newer version, and that probe consumes the remainder of the same five-second initialization deadline. Only a successfully parsed version below 2.45 is cached as a version incompatibility; a timeout, nonzero exit, or malformed response is a non-cacheable `git_version_probe_failed` result so a later initialization can retry. The helper never executes the mutable source path. Before each command, it reopens the snapshot with required no-follow/nonblocking flags, distinguishes identity, content, and access-policy changes, and copies the verified descriptor bytes into a fresh owner-private command launch. It locks the launch directory against ordinary replacement, then repeats descriptor/path identity, access, size, and digest validation before `Popen` executes that copy with the durable source path as `argv[0]`; this preserves native Git runtime-prefix and `%(prefix)` resolution, while the copied-byte version gate fails closed when startup dependencies cannot load from the private runtime location. The self-managed launch directory remains present until the direct child reaches a verified terminal state. If terminal state is unverified, the helper reports a locator only after path revalidation; otherwise it reports the bound directory identity and labels the original path as unverified. Launch-copy and process-group cleanup failures preserve the exact original exception object, type, code, arguments, and traceback while attaching bounded cleanup evidence, including on runtimes without `BaseException.add_note`. The source-snapshot descriptor closes inside that same preparation cleanup flow: an active preparation error remains primary with bounded close evidence, while an otherwise-successful close failure removes the launch copy or reports its retained cleanup locator. Verification, launch copying, process startup, command execution, and the initialization final check consume their single applicable monotonic deadline. These checks prevent blocking on a substituted FIFO but do not claim to preempt a single stalled regular-file kernel operation or a malicious same-UID process that can rewrite owner-private state. The helper ignores ambient Git control/configuration redirections and forbids lazy object fetching. An adoption read establishes one absolute monotonic deadline before repository resolution and binds that resolution, the initial raw index snapshot, one bounded `git cat-file --batch` session, bounded frontmatter parsing and semantic validation, structured per-path validity, and identical final raw index revalidation to the same deadline. Exact OID/type/size/content framing, entry/field/list/issue budgets, duplicate-ID group invalidation, and byte, record, and stderr bounds all fail closed. Validation keeps each exact invalid path once for structured validity decisions. Every user-visible indexed-path diagnostic, including `cat-file` framing/finish errors and frontmatter or semantic limits, renders the full path only through 4 KiB of final UTF-8-with-`backslashreplace` display bytes; longer raw paths use one stable JSON `path_ref` containing their raw byte length and SHA-256 digest. A failed `git ls-files` never echoes stdout; when stderr is empty, it reports only a stable stdout byte-count/SHA-256 reference. Retained issue text keeps its separate existing 1 MiB aggregate ceiling.

The `adoption-status` and JSON `discover-repos` commands recursively render every string through the same UTF-8-safe display boundary before serialization. Filesystem surrogate escapes therefore become literal `backslashreplace` text, including in linked-worktree source paths and nested cleanup evidence, while valid schema keys, machine reason codes, counts, booleans, and nulls remain unchanged; the resulting document always encodes as strict UTF-8. This converter is used only for the fixed adoption document or discovery rows already subject to the command's aggregate row, association, depth, byte, record, path, and retained-error caps, not as a generic unbounded JSON serializer.

Each per-command Git launch binds one lexical absolute temporary-root endpoint without synchronous path canonicalization. Every lexical directory or symlink marker, followed target, and descriptor-bound ancestor must be owned by root or the current user; group/world-writable non-sticky directories and extended ACLs are rejected. The helper retains lexical marker/target identities, ascends and retains descriptor-relative ancestry from that endpoint to the filesystem root, adds the owner-private launch leaf, creates and reopens `git` relative to that leaf, and checks the lexical chain, ancestry, anchored endpoint, and executable identity/access policy immediately before and after `Popen`. A pre-start mismatch launches nothing. A post-start mismatch enters process-group/reap cleanup and makes the launch copy removable only after verified terminal state; otherwise the copy remains. Cleanup runs relative to the held descriptors only after another full check. If a parent was replaced, cleanup fails closed, does not delete the replacement path, and reports bound identity plus an unverified original path hint rather than a false locator. These checks protect point-in-time object identity and access policy at the execution and cleanup boundaries; they do not claim to prevent a malicious same-UID replacement after the final pre-exec check or undo bytes already executed before a post-start mismatch is detected.

Secure bounded configuration and worktree-journal reads use required no-follow/nonblocking descriptors, bind object identity plus access policy and size, and compare one bounded snapshot with a second streamed pass. Worktree journals larger than 1 MiB are rejected from descriptor metadata before any content read. Each pass consumes at most 1 MiB plus one byte; only the first complete snapshot remains retained across passes, while the second uses at most one 64 KiB comparison chunk. Concurrent growth and same-size content replacement therefore fail closed. When a bounded display label is supplied, every message starts with that label and renders `OSError` detail only from its type/errno/strerror, so an original absolute pathname cannot bypass the display bound or be duplicated by the issue collector. An active read, validation, limit, or deadline exception remains the exact primary if descriptor close also fails, with bounded close type, errno, and message evidence. A close-only ordinary failure is wrapped as `UserError` rather than escaping as a raw `OSError`.

Git launch-source and repository-resolution descriptor ownership is retired only after `close(2)` is dispatched under a current-thread POSIX signal mask, or after the descriptor is otherwise proved no longer owned. The fence first queries the entry mask with an empty-set operation, then blocks `SIGINT` plus the helper-managed `SIGHUP`, `SIGTERM`, and `SIGQUIT`; if that second operation changes the kernel mask but raises before returning, the helper attempts one best-effort rollback to the already-known entry mask while FD ownership remains uncommitted. If rollback also fails, it preserves the original failure and reports the thread signal-mask state as unverified. An interruption before successful mask acquisition leaves ownership retryable, while a signal delivered after close dispatch observes ownership already retired and cannot trigger a second close of a reused numeric FD. Persistent mask-acquisition failure leaves the descriptor explicitly owned and each drain invocation visits its entry-time ownership snapshot only once; mask-restoration failure is reported after already-dispatched descriptors are retired. This guarantee covers only the close-dispatch ownership handoff for already-registered descriptors under ordinary selected-signal delivery in the supported single-threaded CLI execution path. It does not cover the separate `open(2)`-return-to-Python-registration window, arbitrary `BaseException` injection from `sys.settrace` or `PyThreadState_SetAsyncExc`, or test/malicious monkeypatches that raise before a mocked `os.close` reaches the kernel.

If `close(2)` and signal-mask restoration both fail, the exact close exception is primary because it carries the descriptor-state uncertainty; restoration failure is retained as bounded evidence with exception type, errno when present, message, and bounded notes. If close succeeds, restoration failure remains primary. Source and repository-resolution wrappers inherit cause notes with contextual deduplication under the same eight-detail and 4 KiB-per-detail limits, while an already-active action exception receives structured cleanup evidence including close exception type and errno. A transient pre-close acquisition failure is described only at that attempt boundary; if an outer drain then closes the descriptor, terminal evidence does not claim that it remains owned. If descriptors are still owned after the final context-exit drain, the selected primary receives one bounded past-tense record of that final boundary.
The helper supports only macOS and Linux and rejects every other platform, including other POSIX systems, before selecting or executing Git; this keeps its bounded process-group and filesystem guarantees explicit instead of silently weakening them. Before `Popen`, it requires default waitable `SIGCHLD` semantics and queries the native `sigaction`: on Darwin and reviewed 64-bit glibc Linux x86_64/AArch64 layouts, it requires a null/default handler and rejects `SA_NOCLDWAIT`, while musl and every other unreviewed machine, libc multiarch, or word-size ABI fail closed before loading libc or starting a child. Inherited `SIG_IGN`, a custom handler, native-handler disagreement, auto-reap policy, or unprovable native layout fails before a child starts. It treats glibc-injected `SA_RESTORER` and its trampoline pointer as private transport metadata rather than a waitability change; restoration coverage still requires the same handler, signal mask, every other flag bit, the exact `SA_NOCLDWAIT` state, and a successfully waitable child. The helper revalidates that property after spawn, before accepting kqueue `NOTE_EXIT` or registration-time `ESRCH`, before non-reaping status observation and final wait, and before every numeric PID/PGID probe or signal. If the property is lost after spawn, it skips all process-group operations and attempts only a nonblocking direct-child reap; any obtained status remains untrusted and the command is `cleanup-incomplete`. When Python exposes POSIX `waitid`, status is observed with `WNOWAIT`. On macOS runtimes without `os.waitid`, including Xcode Python 3.9.6, the parent registers a one-shot kqueue `NOTE_EXIT` observer immediately after `Popen`; registration-time `ESRCH` counts as an already-unreaped direct child only while the waitable-SIGCHLD proof still holds. Both paths keep that unreaped direct child as the PID/PGID identity fence through every bound process-group probe and signal, and the kqueue path obtains the exact return code only from the final post-cleanup `wait()`. After Linux confirms that leader has exited, a bounded `/proc` scan excludes the retained zombie leader while proving whether any live nonleader still belongs to the group; macOS retains signal-zero group probes. Successful and failed commands both complete process-group cleanup before the leader is reaped, so a zero-exit wrapper cannot leave a detached descendant behind. Explicit cleanup ownership states close the async-exception handoff between process-group cleanup and reap-only cleanup; the helper never signals a numeric PGID after the final reap and reports `cleanup-incomplete` if identity, ownership handoff, or cleanup cannot be verified. Error-path cleanup reuses the already claimed ownership object; if cleanup itself raises, only a proven reap-only state permits the final reap, and bounded cleanup exception evidence attaches to the original action exception instead of replacing it.
CLI parsing, including `--help`, completes before Git runtime initialization. Git runtime initialization and one command dispatch then share a single deferred-signal lifetime. Before either begins, the macOS/Linux helper requires working POSIX `pthread_sigmask`, `sigpending`, and synchronous `sigwait` support (using libc `sigwait` when Python does not expose it) and fails closed if any primitive is unavailable. It blocks candidate `SIGHUP`, `SIGTERM`, and `SIGQUIT` signals while installing handlers, leaves `SIG_IGN` and caller-blocked signals untouched, then records only the first managed request without doing cleanup in the handler. Bounded checkpoints route that request through process-group reaping and hook transaction-state reporting. At terminal exit the helper blocks every actually managed signal and unconditionally commits process-private Git runtime cleanup—even after a normal command—before restoring handlers; all Git subprocesses for that command have already finished, and a later in-process `main()` invocation creates a fresh runtime. A terminal cleanup with no retained runtime also clears a cached initialization failure so a repaired `PATH` can retry; incomplete cleanup keeps the retained runtime and locator-bearing error. If terminal mask acquisition fails, outer convergence still commits runtime cleanup, retries the mask only after that commit, and otherwise performs best-safe handler and known-mask restoration plus active-state reset before surfacing the original failure. While still masked it repeatedly uses `sigpending` plus `sigwait` to consume requests that arrived during cleanup or handler restoration, restores the original handlers, requeues only the recorded first signal, and atomically restores the prior mask. Thus `SIG_DFL` terminates, a custom handler runs once and may return, ignored signals remain ignored, and a signal arriving in the final check-to-unmask window sees an already terminal runtime state. When the protected action itself fails, that exact action exception remains primary even if terminal convergence also fails; bounded convergence details, existing action recovery notes, and any retained runtime cleanup locator remain attached as notes, including on Python runtimes without `BaseException.add_note`. Pending-signal reporting reserves its final bounded detail slot for a runtime cleanup issue, so a saturated action-note list cannot hide the retained locator. A cleanup failure is reported with its retained locator before original signal propagation, and the bounded CLI note remains visible when a command error also occurred.
Opt-in hook installation supports macOS and Linux only. It accepts system configuration only when `GIT_CONFIG_NOSYSTEM=1` disables it or `GIT_CONFIG_SYSTEM` names an explicit absolute path; an implicit build-dependent system path fails closed. Explicit system and global Git configuration are snapshotted through required `O_NOFOLLOW|O_NONBLOCK` descriptors, regular-file validation, and bounded double reads without following includes. Effective repository hook configuration is read by one bounded trusted-Git query with `--includes --show-scope --show-origin --type=path --null --get core.hooksPath`; exactly one local or worktree scope/origin/value record is accepted, so includes and worktree precedence are honored while command-level safety configuration cannot mask the real repository value. If no repository value is present, the helper performs the system/global safety preflight and repeats that same repository query once before accepting Git's default hook directory. If either non-repository scope sets `core.hooksPath` or contains an unresolved include, installation stops with an actionable repo-local override that names the durable selected source Git executable rather than a process-private snapshot. Git expands `%(prefix)` and preserves significant leading or trailing whitespace before root constraints are applied. Hook writes bind the complete absolute path from the filesystem root, traverse and create allowed relative components with descriptor-relative no-follow operations, retain and revalidate every ancestor binding, and inspect existing targets with required `O_NOFOLLOW|O_NONBLOCK`. An owner-private lock serializes cooperating installers. Before atomic rename and again after the final installed-target snapshot, the helper re-resolves the effective repository configuration and compares only the semantic hook-plan root and components, then revalidates the bound ancestor chain and lock. A changed plan raises `effective_hook_destination_changed`; query, parse, or safety uncertainty raises `effective_hook_configuration_unverified`. This is point-in-time proof at those verification boundaries, not a continuous configuration lock or a guarantee against change-and-revert. Owner-private same-directory temporary files are committed with native no-replace or exchange rename semantics; an absent-target no-replace `EEXIST` or `ENOTEMPTY` is a definite uncommitted conflict, while any other rename error immediately revalidates exact target and staged snapshots. A proved committed rename continues directory durability and final verification, a proved uncommitted rename cleans its staging file, and an uncertain result preserves and reports the recovery locator. An absent, replaced, or content-changed target otherwise fails closed, and a mismatched exchanged entry is rolled back only while the installed object is still transaction-owned. A failed or uncertain rollback preserves the displaced object under a reported recovery locator. Before displaced-hook deletion, the helper verifies both the displaced and installed objects and enters an explicit installed-target-committed state. That committed state survives temporary-entry consumption, directory fsync, final identity/content/access-policy verification, and effective-destination revalidation, so a failure or asynchronous interruption while that state remains active reports the installed target with the applicable durability, installed-target, or effective-destination step incomplete instead of claiming installation failed or inventing a displaced recovery object. After all final verification succeeds, the state becomes verified and a deferred terminal signal propagates without incomplete or recovery evidence. An asynchronous interruption before the committed state preserves the temporary entry and reports whether it verifies as the displaced-hook recovery object; an interruption during post-commit deletion reports either a retained cleanup locator or completed cleanup and never claims a missing recovery object. Every published recovery or cleanup locator is resolved from the held root-to-directory descriptor chain, accepts renamed components only after a bounded descriptor-relative identity/access-policy match, and is emitted only after revalidating the held directory and leaf object/type/ownership/mode/size/content binding. If the current path cannot be resolved safely, the report marks it `path_unverified` and records structured directory device/inode plus leaf and held-object evidence before closing the descriptors. Target protection covers path and target object identity, type, ownership, access mode, size, and content—not benign timestamp or directory child-entry churn. These checks detect ordinary concurrent installer races; they do not claim to exclude an actively malicious same-UID process that can ignore the protocol and mutate entries after a final verified kernel operation.

Final hook binding cleanup attempts the installation lock and every retained ancestor descriptor even after a failure. After successful acquisition, one POSIX signal fence covers the complete drain, so a pending `SIGINT` cannot run Python between descriptor close dispatches; the binding's complete entry-time owner set retires before the mask is restored, so delayed delivery or a repeated cleanup call cannot close reused numeric descriptors. A close error proves only that dispatch was attempted, leaves descriptor reuse state uncertain, and is never retried. An active operation error remains the exact primary with bounded close, inter-close interruption, and restoration evidence; without one, the first close failure becomes actionable and later close or restoration failures attach to it. A fence-acquisition failure performs no unprotected close, retains ownership for a later retry, and reports the count that remains not close-attempted. A restoration-only error propagates after the complete drain, and a `SIGINT` that became pending while unblocked at entry may be delivered during restore; an entry-blocked pending `SIGINT` remains blocked and pending.

Each installed hook retains the first `min(stream bytes, 64 KiB)` of refresh diagnostics while draining the rest of the producer stream. The portable `dd` stage counts one-byte input records and batches output separately, so a fragmented pipe write cannot consume the record budget early. The producer, bounded-copy stage, and EOF-drain stage publish distinct status records; persistent append is allowed only when both capture stages succeed. A copy/drain failure still consumes the producer as far as the drain permits, skips persistent append, and emits an explicit bounded-partial stderr fallback with both statuses. Under `umask 077`, the hook creates log/status files in one `mktemp` directory, binds independent read/write descriptors, unlinks both names and removes the directory before launching either helper command, and never reopens the captured object by pathname. Persistent-log append opens the resolved Git-path parent with required `O_NOFOLLOW|O_NONBLOCK|O_CLOEXEC|O_DIRECTORY`, then inspects the leaf relative to that descriptor without following links. A stable pre-existing FIFO, symlink, or other non-regular object is rejected before any leaf write-open; an absent leaf is created only with `O_CREAT|O_EXCL`. An existing regular leaf is opened with required `O_NOFOLLOW|O_NONBLOCK|O_CLOEXEC|O_APPEND`. The helper requires a current-user-owned, non-group/world-writable, ACL-free parent and regular-file leaf, binds their exact object identities and owner/group/mode access policies, writes only through the held leaf descriptor, and revalidates both path bindings before and after the append. An unsafe policy, replacement, exclusive-create conflict, or inspection failure returns to the hook's stderr fallback. If persistent append otherwise cannot start or fails after launch, the hook emits the bounded capture through its independent stderr descriptor. It ignores `SIGPIPE` and individual stderr-write failures before the explicit zero exit, so a closed diagnostic sink cannot reject the Git operation. Secure-buffer setup failure emits a fixed message and cleanup is non-recursive. The append checks protect point-in-time object identity, type, and access policy rather than content stability because the file is intentionally extended; they do not exclude malicious same-UID replacement or change-and-revert between checks and the write-open, or preempt a stalled regular-file kernel write. The anonymous-buffer checks protect the captured objects after descriptor binding and unlink, not against a malicious same-UID replacement before that boundary, and they do not claim that an open but permanently non-consuming external stderr sink cannot block a synchronous write.
Repository discovery streams both active `sessions` and flat `archived_sessions` rollouts through one shared 60-second monotonic deadline and aggregate caps of 131,072 filesystem entries, 256 bound rollout-directory levels, 8,192 logical rollouts, 256 MiB each for logical rollout input and its second-pass verification reads, 4 MiB per line, 1,000,000 records, 4,096 normalized distinct CWDs, 131,072 retained logical rollout associations across resolved and unresolved candidates, JSON depth 64, 4,096 digits per JSON integer, 16 KiB of strict UTF-8 per CWD, 256 CWD components, and 32 retained scan errors. The two sources share every counter and never reset either byte ceiling. The archive source accepts only direct `rollout-*.jsonl` children; nested directories and their contents are skipped before no-follow stat or traversal. Candidate selection matches each accepted `rollout-*.jsonl` name before no-follow type inspection, so a stable symlink, FIFO, directory, or enumeration-time inspection failure becomes structured partial coverage instead of being silently filtered out. An inspection failure is ignored as outside the requested window only when a parsed session partition/archive name or that enumerated candidate's own modification time reliably proves it predates the cutoff; uncertainty remains partial coverage and consumes the shared error budget. Directory enumeration uses a descriptor-relative `O_DIRECTORY|O_NOFOLLOW|O_NONBLOCK` walk from each rollout root, opens children relative to held parents, and revalidates the bound chain before consuming or handing off entries. Directory protection covers object identity (`st_dev`, `st_ino`) and access policy (`st_uid`, `st_gid`, permission mode), so missing, unreadable, replaced, or policy-changed directories are distinct partial-coverage failures while timestamp, link-count, and child-entry churn alone remain acceptable. Enumeration records each regular rollout's object identity, access policy, and content size separately. Parsing reopens that exact object with required `O_NOFOLLOW|O_NONBLOCK`, rebinds the path, and then repeats a deadline-checked digest read bounded by the exact first-pass size before final descriptor/path revalidation. A FIFO, symlink, unreadable path, true object/path replacement, access-policy change, append/truncation or same-size content change marks coverage partial with the corresponding distinct `inspection_reason`; content or policy drift is never mislabeled as object replacement. Physical active/archive files with the same rollout basename are both consumed and their CWD evidence is unioned, while each repository association contributes only once to the logical `rollout_count`; an unreadable, malformed, invalid-UTF-8, NUL-bearing, or otherwise unprovable copy makes coverage partial instead of being hidden by basename deduplication. Strict UTF-8 encoding, NUL rejection, and CWD byte/component caps are enforced before `Path` construction or repository fallback. Each accepted rollout stores normalized distinct CWDs in first-seen order in a per-rollout buffer. Repository resolution, adoption enrichment, and association begin only after the second read and final descriptor/path/content revalidation finish and the rollout descriptor closes. A failed rollout discards its pending buffer without rolling back aggregate byte, record, verification-byte, or distinct-CWD counters. The caller explicitly owns and closes both yielded iterators before coverage serialization. On invalid-CWD, deadline, limit, or retained-error-cap early exit, the selected scan error remains primary; descriptor and directory-frame close failures are ordered bounded `cleanup_errors`, do not consume additional retained-error slots, and cannot disappear with `GeneratorExit`. Each selected error freezes its coverage counters before cleanup, sheds traceback/context/cause references once it will no longer be re-raised, and is serialized only after cleanup completes. `coverage_status: complete` proves the candidate scan stayed within those bounds. A deadline, limit, non-empty record parse failure, invalid CWD, or source I/O failure preserves rows committed by earlier verified rollouts, while the failing rollout contributes no pending rows, and marks every row `partial`; one deterministic final-sort anchor retains the full bounded `discovery_coverage` object with a stable `coverage_id`, while every partial row carries a small `discovery_coverage_ref` to that ID and keeps any row-local error. A no-repository sentinel is both the anchor and a referring row. Consumers must resolve each partial row's reference to the single matching anchor and must not interpret a partial or sentinel result as a complete candidate set.

Rollout CWDs are literal filesystem paths, not shell input. Discovery never expands a leading tilde; relative and tilde-prefixed spellings remain ignored as non-repository evidence.

Date evidence is derived only from the candidate path relative to the explicit rollout root, never from similarly named outer ancestors. For rollout directories, the protected signals are object identity (`st_dev`, `st_ino`), access policy (`st_uid`, `st_gid`, permission mode), and directory type. Every directory error handoff revalidates the retained ancestor chain first and reports an ancestor identity or access-policy failure in preference to a coincident child scan/open/stat error. Once that structured primary failure is selected, bound frames and descriptors are closed before handoff; a close failure is retained as bounded `cleanup_errors` evidence without replacing the primary failure, while cleanup errors still propagate normally when no primary failure exists. Rollout-file candidate binding and extraction use the same precedence: descriptor-close faults attach to the current parse, limit, replacement, or access-policy error and serialize with it instead of escaping generator cleanup.

Within that bounded candidate set, `adoption_status` is the authoritative `adopted`, `unadopted`, or `inconclusive` tag; inconclusive rows include a structured `adoption_error` and null adoption fields, and consumers must not use them as unadopted evidence. Each candidate gets one absolute deadline, capped by the aggregate scan deadline, before bounded repository resolution. Resolution, adoption, journal enumeration, generated-index classification, exclude lookup, hook resolution and inspection, and index presence checks all consume that same deadline instead of resetting independent timeouts. After a failed `git rev-parse`, repository resolution uses the remainder of that deadline for a descriptor-bound scan over at most `MAX_DISCOVERY_CWD_COMPONENTS + 1` existing ancestors. It opens the retained lexical current path once with required `O_DIRECTORY|O_CLOEXEC|O_NONBLOCK` and deliberately omits `O_NOFOLLOW` so a stable final symlink keeps kernel path semantics; the resulting descriptor must identify the same `(st_dev, st_ino)` directory observed before Git. Every `.git` classification then uses only no-follow `stat(".git", dir_fd=current_fd)`, and every parent uses only `open("..", dir_fd=current_fd)` with required `O_DIRECTORY|O_NOFOLLOW|O_CLOEXEC|O_NONBLOCK`; a bound parent is acquired before the prior descriptor closes, and at most current plus parent are held. One descriptor owner is authoritative across open registration, handoff, and context exit; `current_fd` and `parent_fd` are non-owning aliases, and each owner entry records whether close has not started or has already been attempted. A line-level asynchronous `BaseException` before close therefore leaves the entry available for one real close, while an interruption after close never retries that numeric descriptor. Context exit retries an interrupted drain, completes before terminal return, and preserves the exact active classification primary. With no earlier primary, the first uncertain close failure and its cause persist in the owner across any later drain interruption; later close or interruption evidence is secondary. Early recovery is admitted only after the owner marked a close attempt and only when the contextual exception differs by identity from the ambient exception recorded at close start, so an outer Git/classification exception is never relabeled as a close failure. The scan never opens, parses, or follows a marker, and it stops at the descriptor-proved root or starting-device boundary. Only a complete point-in-time no-marker scan whose descriptors all close successfully returns an ordinary non-repository result. Any marker type, initial identity mismatch, unsupported descriptor primitive, inspection failure, deadline, persistent `ENOTDIR`, scan-limit exhaustion, or uncertain close produces structured `repository_resolution_failed` evidence. Marker evidence binds its kind, ancestor level, directory device/inode, and an explicitly `path_unverified` lexical hint rather than claiming a verified marker pathname; a marker never proves a repository root. An active classification error remains primary when descriptor cleanup also fails, and bounded `cleanup_errors` are serialized with it. This proves the post-Git ancestor relation through held descriptors; it does not claim a continuous lock across the earlier Git invocation or protection from an endpoint-invisible pre/post identity ABA. When another CWD resolves to the same root with at least one additional second of remaining budget, a still-inconclusive adoption check receives one retry; each root is enriched at most twice, so persistent failures remain bounded. Auxiliary per-repository failures produce a field-keyed structured `discovery_error` and null only the affected auxiliary fields without erasing authoritative index adoption or aborting healthy repository rows. Generated-index marker, exclude, and hook reads require no-follow/nonblocking descriptors bound to stable regular files and enforce hard retained-byte ceilings; the marker classifier reads only a 4 KiB/2 KiB-per-line three-line marker prefix. A truly missing entry is an authoritative negative, while a deadline, EACCES, EIO, FIFO, symlink, directory, unstable file, or oversized input produces structured partial/limit evidence and leaves only the affected field unknown. Inaccessible journal, index, exclude, or hook paths therefore remain unknown rather than becoming false or zero. In particular, unresolved effective hook configuration makes `hooks_installed` null and the discovery row inconclusive; `false` remains reserved for an authoritative negative check.

For a Git root beneath the selected `$CODEX_HOME/worktrees`, discovery performs bounded secondary `--git-dir` and `--git-common-dir` lookups before publishing any repository or install/generate command. It returns the discovered root only when both lookups succeed, their path framing is valid, and their normalized paths prove a standalone repository. A distinct common directory must independently resolve to a distinct source repository. An unsupported or changed Git runtime, lookup failure, malformed output, unresolved source, or self-mapping source instead emits structured `repository_resolution_failed` evidence with reason `codex_worktree_mapping_unverified`; it never falls back to the disposable Codex worktree.

## Cleanup failure precedence

Snapshot cleanup during creation, the version probe, or final validation follows the same failure precedence as launch cleanup: an active failure remains the exact primary exception with bounded retained-locator evidence, while a cleanup failure with no active exception becomes the reported initialization failure.

Terminal runtime cleanup converts an ordinary `Exception` into the locator-bearing cleanup issue. A non-`Exception` `BaseException` such as `KeyboardInterrupt` or `SystemExit` instead receives bounded retained-locator evidence. When that interruption is the sole terminal failure and no managed signal is being propagated, it is re-raised without replacement, preserving the same object, type, arguments, and traceback. Against the cleanup failure, an active action exception remains primary and receives the cleanup evidence; existing precedence for an earlier terminal-convergence failure or managed-signal propagation is unchanged.

If cleanup of an uncommitted hook staging entry fails while another installation error is active, that exact installation error remains primary and receives bounded descriptor-bound locator evidence after path verification; an unresolved path is reported as structured `path_unverified` evidence instead. Without an active error, the cleanup failure is reported on its own.

After hook durability, installed-target, and effective-destination verification all pass, `mark_verified()` enters a distinct verified terminal phase. A deferred SIGHUP, SIGTERM, or SIGQUIT observed at the final checkpoint then propagates without false incomplete-verification or recovery evidence; only interruptions in earlier post-commit phases report their applicable pending step.
